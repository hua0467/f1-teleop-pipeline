## 0. 前置准备（仅首次）

**新电脑第一次用的时候跑一遍，之后不用。**

### 0.1 检查 Python 环境

打开 CMD 或 PowerShell，敲：

```cmd
cd C:\Users\Administrator\Documents\f1-teleop-pipeline
python scripts\01_test_environment.py
```

看到「7 个必需包全部到位。可以开始录数据了。」就是 OK。

如果提示缺少包，运行它提示的安装命令（一般是 `python -m pip install ...`）。

### 0.2 确认 URDF 文件

```cmd
dir urdf\F1_URDF_V04.urdf
```

文件存在就行。这是 F1 机器人的运动学模型，IK 求解器需要它。

## 1. 每日开机

到了工位后，按这个顺序，5 分钟到位。

### 1.1 电脑网络确认

Quest 3 通过 WiFi 发数据到电脑，电脑网络必须是「专用网络」。

```powershell
powershell Get-NetConnectionProfile
```

看 `NetworkCategory` 这一行，必须是 **Private**。

如果是 Public，改成 Private：

```powershell
Get-NetConnectionProfile | Set-NetConnectionProfile -NetworkCategory Private
```

> 为什么：Windows 公用网络模式会拦 UDP 数据包，Quest 3 的数据进不来。

### 1.2 查看电脑 IP

```cmd
ipconfig | findstr "IPv4"
```

记住 `192.168.x.x` 那个地址。通常是你连接 WiFi 的那张网卡。

> 如果哪天 IP 变了，需要把新 IP 填到 Quest 3 App 里。

### 1.3 Quest 3 连 WiFi

1. Quest 3 开机（长按左侧电源键 3 秒）
2. 设置 → Wi-Fi → 连接公司 WiFi
3. 确认 Quest 3 和电脑连的是**同一个 WiFi**

> 怎么验证：Quest 3 的 IP 应该也是 `192.168.x.x`（前三位一样）。

## 2. 启动平台

### 2.1 终端启动

打开 CMD（或 PowerShell），敲：

```cmd
cd C:\Users\Administrator\Documents\f1-teleop-pipeline
python scripts\08_realtime_visualizer.py
```

终端会显示：

```
+==========================================================+
|  F1 VR 遥操数据实时可视化平台                             |
|  >> 浏览器打开: http://localhost:8765                     |
|  UDP 端口: 9000                                          |
|  IK 状态: [OK] 已加载                                     |
+==========================================================+
[UDP] 监听 0.0.0.0:9000，等 Quest 3 发数据...
[LOOP] 开始处理，30 FPS
```

**终端不要关，保持开着。**

### 2.2 浏览器打开仪表盘

浏览器地址栏输入 `localhost:8765`，回车。

你会看到一个暗色背景的仪表盘页面。

页面结构（从上到下）：

```
┌─ 顶栏 ───────────────────────────────────────────┐
│ ●状态灯  帧率 XX  运行时间  总帧数                │
│ 右IK X/X  左IK X/X          [● 开始录制] [清告警] │
├──────────┬───────────────────────────────────────┤
│ 左侧面板  │        右侧图表区（3张曲线图）          │
│ 关节角    │         躯干(3轴)                      │
│ 数字读数  │         右臂(7轴)                      │
│          │         左臂(7轴)                      │
├──────────┴───────────────────────────────────────┤
│ 底部告警栏                                         │
└──────────────────────────────────────────────────┘
```

**状态灯含义：**

| 灯色 | 含义 | 说明 |
|------|------|------|
| 🔴 红 | 未连接 | 平台刚启动，等 3 秒自动变黄。一直红 = 刷新浏览器 |
| 🟡 黄 | 等待数据 | 平台正常，但 Quest 3 还没发数据过来 |
| 🟢 绿 | 数据正常 | Quest 3 在发，IK 在算，一切正常 |

## 3. Quest 3 准备

### 3.1 打开 Hand Tracking Streamer

1. 戴上 Quest 3 → 按右手柄 O 形键（Meta 键）
2. 点击右下角 9 个圆点（应用库）
3. 右上角下拉菜单 → 选「未知来源」
4. 找到 **Hand Tracking Streamer** → 打开

### 3.2 检查配置

看 App 界面上显示的：

| 设置项 | 应该是什么 |
|--------|-----------|
| 目标 IP | `192.168.9.2`（你的电脑 IP） |
| 端口 | `9000` |
| 协议 | UDP |
| 追踪模式 | Hands: **Both**（左右手都追） |
| Show Landmarks | ✅ 开启 |
| Debug Info | ✅ 开启 |

> IP 如果跟你电脑的不一样，在 App 里改过来。

### 3.3 启动数据传输

**关键操作**：点一下 **Stop**，再点 **Start**。

> 为什么：App 开久了会休眠，Stop→Start 能唤醒它。这个坑踩过很多次了。

点完 Start 后：
1. 把手放到 Quest 3 镜头前晃动
2. Quest 3 屏幕上应该出现彩色的手部追踪点
3. 回头看电脑浏览器——**状态灯应该变绿**，左侧关节角数字开始跳动，右侧曲线开始画

如果状态灯一直是黄的（没收到数据），跳到 [7. 故障排查](#7-故障排查)。

## 4. 录制数据

### 4.1 录制前确认

在浏览器仪表盘上确认：

- [ ] 状态灯是 🟢 绿色
- [ ] 关节角数字在跳动（不是全 0）
- [ ] 右侧曲线在动

### 4.2 开始录制

1. 点击顶栏的 **● 开始录制**
2. 按钮变成红色闪烁 **■ 停止录制** → 录制中
3. 对着 Quest 3 做动作

**录制建议：**

| 项目 | 建议 |
|------|------|
| 每组时长 | 15-30 秒 |
| 动作 | 单一任务，不要混杂（如只做「拿水瓶」这一个动作） |
| 命名 | 录制前心里想好这组叫什么（如「01-拿水瓶」） |
| 手部 | 只用一只手即可（通常左手做动作，右手扶着眼镜） |
| 节奏 | 慢一点，动作连贯不要停顿 |

### 4.3 停止录制

1. 动作做完 → 点击 **■ 停止录制**
2. 底部告警栏会出现绿色提示：`录制完成: XX 帧 → episode_XXXX.h5`
3. 然后自动生成 LeRobot 格式：`已生成 LeRobot: episode_XXXX.parquet`

### 4.4 重复录制

重复 4.2-4.3，录 3-5 组即可。每组的文件名会自动递增（episode_000014, episode_000015...），不会覆盖。

### 4.5 退出

所有录制完成后：
1. 关闭浏览器页面
2. 回到终端，按 **Ctrl+C** 停止平台
3. Quest 3 上退出 Hand Tracking Streamer

## 5. 数据交付

### 5.1 数据在哪

录制生成的文件在这两个位置：

| 格式 | 路径 | 用途 |
|------|------|------|
| HDF5（原始存档） | `f1-teleop-pipeline\recordings\episode_XXXX.h5` | 备份、复现 |
| LeRobot（训练用） | `f1-teleop-pipeline\datasets\f1_vr_v1\data\chunk-000\episode_XXXX.parquet` | 发给学驰 |

> parquet 是二进制格式，用 `pd.read_parquet()` 打开，记事本打开是乱码（正常现象）。

### 5.2 桌面打包

```cmd
# 复制数据集到桌面并打包
xcopy /E /I /Y datasets\f1_vr_v1 "C:\Users\Administrator\Desktop\F1数据交付\f1_vr_v1_数据集\"
```

然后右键桌面 `F1数据交付` 文件夹下的 `f1_vr_v1_数据集` → 发送到 → 压缩文件夹。

## 7. 故障排查

### 问题 1：状态灯一直是黄的（没数据）

**顺序排查：**

1. Quest 3 和电脑连的是同一个 WiFi 吗？
2. Quest 3 App 里点过 **Stop → Start** 了吗？
3. Quest 3 屏幕上能看到手部追踪点吗？（看不到 = App 没在追手）
4. 电脑网络是 Private 吗？（`powershell Get-NetConnectionProfile`）
5. Quest 3 App 里的 IP 是电脑 IP 吗？（`ipconfig` 确认）

**终极测试**——检查 UDP 链路是否通畅：

```cmd
# 先 Ctrl+C 停掉可视化平台
# 运行这个：10 秒内收到包 = 链路通，没收到 = Quest 3 没发
python -c "import socket; s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM); s.bind(('0.0.0.0',9000)); s.settimeout(10); d,a=s.recvfrom(65535); print('收到！',len(d),'字节 来自',a)"
```

如果这个也收不到，问题 100% 在 Quest 3 那边（App 没启动、IP 错了、WiFi 断了）。

### 问题 2：平台启动报错「端口被占用」

```cmd
netstat -an | findstr "8765"
```

如果 8765 被占了，换个端口：

```cmd
python scripts\08_realtime_visualizer.py --web-port 8766
```

浏览器打开 `localhost:8766`。

### 问题 3：浏览器打不开 localhost:8765

1. 终端还开着吗？没关才能访问
2. 试试 `http://127.0.0.1:8765`

### 问题 4：关节角全是 0

可能是 IK 求解器没加载成功。看终端启动时有没有打印 `[IK] F1 Kinematics loaded`。

如果没有，检查 URDF 文件：

```cmd
dir urdf\F1_URDF_V04.urdf
```

### 问题 5：录制按钮点了没反应

已修复。现在点了立刻变样（红色闪烁）。如果还是不响应，刷新浏览器。

### 问题 6：Quest 3 App 找不到了

App 在「未知来源」里，不在主应用列表。Quest 3 右上角下拉 → 选「未知来源」。

## 附录 A：命令行备用方案

如果浏览器打不开或者不想用仪表盘，可以用纯命令行录制：

### A.1 命令行录制（无 IK）

```cmd
cd C:\Users\Administrator\Documents\f1-teleop-pipeline

# 录制 20 秒，存到 recordings/
python scripts\05_quick_record.py --duration 20 --fps 30
```

### A.2 离线跑 IK

录完后再跑 IK 解算 + 转 LeRobot：

```cmd
# 找到刚才录的 HDF5 文件（最新的那个）
dir recordings\episode_*.h5 /O-D

# 跑 IK（把文件名换成实际的）
python scripts\07_offline_ik.py --input recordings\episode_000014.h5 --dataset f1_vr_v1
```

### A.3 跑环境检查

```cmd
python scripts\01_test_environment.py
```
